# RAG 检索评测集

这套评测用来在固定语料下，量化对比三档检索策略的召回质量，为项目的 RAG 指标提供可复现的实验依据。

## 它要回答的问题

同一份知识库、同一批问题，下面三种检索方式各能召回多少正确内容：

1. 纯向量检索（pgvector 相似度）
2. 向量 + 关键词混合检索（RRF 融合）
3. 混合检索 + rerank 重排

跑出来的对比能直接支撑「加了混合检索召回率提升多少、再加 rerank 又提升多少」这类结论。

## 语料（本地准备，不进 git）

评测语料是 3 份 Java 后端面试 PDF，属于第三方版权资料，体积也大，所以不纳入版本控制（已在根目录 `.gitignore` 忽略 `456/`）：

- `面渣逆袭Redis篇V2.0.pdf`
- `面渣逆袭MySQL篇V2.2.pdf`
- `面渣逆袭-分布式篇.pdf`

仓库里只保留评测集本身（`eval-dataset.yaml`）和评测代码。任何人要复现，只需自行准备这 3 份 PDF。

### 入库步骤

1. 启动后端和依赖（pgvector + Redis + 对象存储）。
2. 通过知识库上传接口把这 3 份 PDF 传进去，等向量化完成（状态变为 `COMPLETED`）。
3. 记下生成的知识库 ID，评测时通过配置传入（见评测测试说明）。

入库走的是项目真实的上传链路（Tika 解析 → 切片 → 向量化 → pgvector），所以评测结果反映的是线上实际表现，不是脱离实现的玩具实验。

## 评测集结构（`eval-dataset.yaml`）

共 42 题：Redis 18、MySQL 16、分布式 8。每题包含：

| 字段 | 含义 |
|------|------|
| `id` | 唯一编号 |
| `source` | 期望命中的来源文档（`redis` / `mysql` / `distributed`），用于文档级判定 |
| `difficulty` | 难度：`fact`（直接事实）/ `concept`（概念理解）/ `synthesis`（跨段综合） |
| `question` | 检索查询，贴近真实面试问法 |
| `key_points` | 必含关键点组，用于关键词级判定 |

### ground truth 判定方式

采用「关键词级为主、文档级为辅」，不依赖脆弱的 chunk 编号（切片参数一变 chunk 编号就失效）：

- **关键点覆盖率**：每个关键点是一组同义词候选，检索 topK 结果拼接文本命中其中任一即算该点命中。命中关键点数 / 总关键点数，就是该题的关键点覆盖率。这是衡量「检索内容能不能支撑答对问题」的核心指标。
- **来源命中**：topK 里是否含有来自期望文档的片段，作为辅助指标。

## 指标

- **关键点覆盖率**（主）：平均每题命中多少比例的关键点。
- **来源命中率**（辅）：期望来源文档进入 topK 的题目比例。
- 按 `difficulty` 和 `source` 分组统计，便于定位哪类问题检索效果差。

三档策略各跑一遍，对比即得收益结论。
